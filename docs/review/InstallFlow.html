Fusion360 Linux Installation Pipeline

Architecture Overview

The installer is a modular, idempotent pipeline. It detects the system environment, prepares a localized Proton prefix, installs necessary Windows dependencies, and configures runtime environment variables before launching the Autodesk downloader. Each script is a self-contained, numbered step sourced by the thin install.sh wrapper.

    [install.sh] (thin wrapper)
        │
        ├─▶ 00-defaults.sh      — XDG path constants
        ├─▶ 00-common.sh        — Distro detection, shared utils
        ├─▶ 10-deps.sh          — System packages (apt/dnf/pacman)
        ├─▶ 20-ge-proton.sh     — Download GE-Proton
        ├─▶ 25-install-to-location.sh — Copy scripts to ~/.local/share/
        ├─▶ 30-prefix.sh        — Wine prefix init + VC++ runtimes
        ├─▶ 35-webview2.sh      — Microsoft Edge WebView2
        ├─▶ 37-config.sh        — ~/.config/fusion360-linux/config
        ├─▶ 40-fusion-installer.sh — Main app download + desktop entries

Step-by-Step Breakdown

#StepActionKey Paths Written
1Dependencies Installs required system packages (wine, winetricks, curl, xdg-utils, etc.) via distro-specific package manager System-wide (via sudo)
2GE-Proton Downloads and extracts GE-Proton from GitHub if not already present ~/.local/share/Steam/compatibilitytools.d/
3Install to Location Copies runtime scripts to data dir, creates symlinks in bin dir ~/.local/share/fusion360-linux/, ~/.local/bin/
4Prefix Initializes Wine prefix, sets Windows version to win10, installs VC++ runtimes via winetricks ~/.fusion360-proton2/pfx/
5WebView2 Downloads and installs Microsoft Edge WebView2 runtime into the prefix ~/.fusion360-proton2/pfx/
6Config Generates config file with DPI settings, Proton path, prefix path, browser, env var toggles ~/.config/fusion360-linux/config
7Protocols Registers URI handlers (adsk://, adskidmgr://) and Wine browser bridge ~/.local/share/applications/fusion360-linux/, prefix registry
8Installer Downloads and runs the Autodesk webdeploy streamer. On completion, creates autodesk-fusion360.desktop entry ~/.fusion360-proton2/pfx/, desktop entry

System Changes

  • System packages: wine, winetricks, curl, zenity, xdg-utils, xdotool, moreutils, etc. (distro-specific)
  • Desktop entries: Fusion 360 launcher + callback handler in ~/.local/share/applications/fusion360-linux/
  • MIME associations: x-scheme-handler/adsk and x-scheme-handler/adskidmgr registered via xdg-mime
  • CLI symlinks: fusion360, fusion-status, fusion-doctor, fusion-uninstall in ~/.local/bin/
  • Wine registry: DPI (LogPixels, Win8DpiScaling), WineBrowser paths, Windows version set to win10

Re-run Behavior (Idempotency)

The pipeline is designed for safe re-entry. Each step checks for prior completion:

  • 10-deps.sh: Skips packages already installed (via package manager)
  • 20-ge-proton.sh: Checks if proton binary exists in compatibilitytools.d
  • 30-prefix.sh: Checks if pfx/user.reg exists
  • 35-webview2.sh: Checks if WebView2 is already installed in the prefix
  • 37-config.sh: Adds missing config keys if config exists; skips if all present
  • 40-fusion-installer.sh: Checks autodesk.webdeploy.streamer.log for "Configure app complete"

This makes re-running bash install.sh safe at any point — completed steps are detected and skipped.
