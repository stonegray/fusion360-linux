PyShellBoundary: Python / Shell Boundary Analysis

This report analyzes the functional split between Python and Shell scripts in the Fusion360 Linux Launcher.

File:Function Current Recommended Issue / Rationale Severity Effort
launcher-functions.sh:resolve_fusion_wine_dpi Shell Python Logic Duplication. Shell implementation is a manual rewrite of the Python logic. Shell is fragile for complex desktop config parsing (GSettings, KDE kreadconfig). Python has better error handling and libraries for this. Medium Low
launcher-functions.sh:apply_fusion_wine_dpi Shell Python Registry Patching. Uses sed to patch user.reg. This is extremely fragile and can corrupt the registry if line breaks or sections differ. Python can handle registry file parsing/writing much more safely. High Med
launcher-functions.sh:register_wine_browser_bridge Shell Python Registry Patching. Similar to DPI patching, it appends to the registry. Should be moved to a unified Python "Registry Manager" for consistency and safety. High Low
health-check.sh Shell Python Heuristic Blindness. Currently only checks file existence. Python could perform deeper validation (e.g., checking if Fusion360.exe is the correct version, validating config keys, checking Proton version compatibility). Medium Med
launcher-config-user-interface.py Python Python GUI / Interaction. Python + Tkinter is ideal here. Shell-based zenity or dialog is too limited for the complex configuration required. Low N/A
launcher-functions.sh:apply_launch_environment Shell Shell Environment Export. Shell is the natural place for export. Calling Python to export env vars to a parent shell is unnecessarily complex. Low N/A
00-common.sh:kill_installer Shell Python (Helper) Process Management. Complex grep/pgrep logic to find Wine processes. Python psutil (if available) or more robust parsing of /proc would be more reliable on various distros. Medium Med
launcher-functions.sh:save_config Shell Python Config Marshalling. Shell uses heredocs. Moving to Python allows for JSON/YAML or more robust shell-safe escaping without manual printf %q. Low Low

Strategic Recommendation

Proposal: Transition to a Python-Driven Core with Shell Entrypoints.

  • Python: Logic, Config Validation, Registry Patching, DPI Resolution, Health Checks.
  • Shell: Process bootstrapping, Environment variable orchestration, and launching child processes.

Benefit: significantly simplifies testing (Python unittest), improves reliability for registry edits, and eliminates logic duplication.

Cost: Hard dependency on python3-tk (already required for UI) and potentially psutil (optional but recommended).
