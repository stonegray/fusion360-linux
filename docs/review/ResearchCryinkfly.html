Research: Cryinkfly vs Fusion360 Linux — Comparative Analysis

Source: codeberg.org/cryinkfly/Autodesk-Fusion-360-on-Linux

Date: 2026-07-28

Note: Cryinkfly's core is a single ~1880-line monolithic bash script (files/setup/autodesk_fusion_installer_x86-64.sh) plus supporting launcher/desktop scripts. Our repo is modular with separate install steps, runtime functions, doctor, and a Python config UI. This review compares approaches and identifies actionable items.

Notable Findings

Patterns We Should Adopt

1. Broader distro coverage (Cryinkfly ~18+ vs our 7)

Cryinkfly covers Alpine, CentOS, Clear Linux, Deepin, Devuan, EL, Gentoo, Mageia, NixOS, OpenMandriva, RHEL, Rocky, Slackware, Solus, Tumbleweed, Void, and more. Many use identical package names (icoutils, zenity, cabextract, etc.). Could add detection for these with minimal effort since our distro/*.txt pattern makes adding new distros trivial.

2. More comprehensive wine prefix initialization

Cryinkfly's prefix setup (lines ~1680-1820) includes more winetricks verbs:

  • sandbox, corefonts, cjkfonts, dotnet20, dotnet48, vcrun2022
  • atmlib, gdiplus, msxml4, msxml6, fontsmooth=rgb, winhttp
  • Registry tweaks: Windows 11 version, disabled adpclientservice.exe tracking
  • Symlinks DeviceSettingsProvider.dll → fabricapplication.dll (workaround for Fusion crash)

Recommendation: Add atmlib gdiplus corefonts winhttp fontsmooth=rgb to our winetricks invocation, and the DeviceSettingsProvider.dll symlink.

3. GPU / VRAM / RAM pre-flight checks

Cryinkfly (lines ~730-850) checks GPU driver vendor, deduces correct Vulkan ICD, and skips DXVK on NVIDIA. They also check available RAM/disk before installing.

Recommendation: Add GPU detection to our doctor module. We already check disk space in pre_flight() — keep that.

4. GNOME "not responding" dialog workaround

Cryinkfly sets G_MESSAGES_DEBUG=none and tweaks GNOME's org.gnome.mutter check-alive-timeout. Fusion under Wine often appears hung to GNOME's watchdog.

Recommendation: Add environment variable to our apply_launch_environment() in launcher-functions.sh.

5. Multi-install tracking

Cryinkfly numbers install directories (~/.local/share/applications/wine/Programs/Autodesk/<N>/) and logs each install in installs.log. Their swap_desktop_files.sh cycles between active installs.

Recommendation: Consider for future feature, but lower priority than the prefix/driver improvements.

6. Online version check in launcher

Cryinkfly's autodesk_fusion_launcher.sh fetches build-versions.txt from Autodesk and warns if the local Fusion version is stale. Useful power-user feature.

Anti-patterns / Things to Avoid

1. Monolithic script

Their single 1880-line file is hard to maintain, review, or parallelize work on. Our modular approach is strictly better.

2. Hardcoded paths

Cryinkfly hardcodes $HOME/.wineprefixes/fusion360 and other paths throughout the script. Our XDG-based 00-defaults.sh is more standards-compliant.

3. Silent winetricks failures

Cryinkfly runs winetricks with 2>/dev/null || true, silently swallowing all errors. Our winetricks -q vcrun2022 2>/dev/null || true is similarly silent — we should at least log warnings.

4. No formal error handling

Cryinkfly has almost no set -euo pipefail guards or error handling on critical operations.

Interesting / Neutral Differences

Desktop file management

Cryinkfly adds extra StartupWMClass=fusion360.exe and Actions=NewWindow; to desktop entries. Minor polish.

Wine build management

Cryinkfly supports custom Wine builds (TKG, etc.) in addition to Proton. Our current approach is Proton-only which simplifies things significantly — keeping it simple is fine.

WebView2

Cryinkfly doesn't install WebView2 separately (relies on Wine's built-in). Our 35-webview2.sh goes further.

Recommendations Ranked

  1. Expand distro coverage — Add Alpine, CentOS, Gentoo, Void, NixOS, Slackware, Mageia, OpenMandriva, Clear Linux, Deepin, Devuan to detect_distro() and create distro/*.txt files. Package names are nearly identical.
  2. Add more winetricks verbs — atmlib gdiplus corefonts winhttp fontsmooth=rgb before or alongside vcrun2022. Add the DeviceSettingsProvider.dll → fabricapplication.dll symlink workaround.
  3. Add GPU detection to doctor — Check glxinfo/vulkaninfo for driver vendor and version. Report issues with missing or outdated drivers.
  4. Add GNOME watchdog workaround — Set G_MESSAGES_DEBUG=none in apply_launch_environment(), and optionally try to disable check-alive-timeout.
  5. Add online version check — Optional feature for the launcher: check Autodesk's build-versions.txt and warn if outdated.
  6. Upgrade silent || true to warnings — Replace winetricks -q ... 2>/dev/null || true with || echo "Warning: ..." so failures are visible.
