Layout Proposal — GitHub-Ready Directory Structure

Proposed Public Repo Layout

├── bin/                    # CLI entry points (symlinked to ~/.local/bin/)
│   ├── fusion360           # Launch Fusion 360
│   ├── fusion360-install   # Run installer
│   ├── fusion360-uninstall # Remove installation
│   ├── fusion360-doctor    # Diagnostics
│   └── fusion360-config    # Config UI (Python TUI)
├── src/
│   ├── core/
│   │   ├── bootstrap.sh    # Environment/path init
│   │   └── utils.sh        # Shared helpers (log, error, die)
│   ├── modules/
│   │   ├── proton.sh       # Wine/Proton management
│   │   ├── dpi.sh          # DPI detection & resolution
│   │   ├── browser.sh      # OAuth browser bridge
│   │   ├── paths.sh        # XDG path resolution
│   │   └── desktop.sh      # Desktop entry & protocol handler
│   ├── install/
│   │   ├── deps.sh         # Dependency install (distro-aware)
│   │   ├── prefix.sh       # Wine prefix setup
│   │   ├── config.sh       # Config generation
│   │   └── fusion-installer.sh  # Main Fusion installer
│   ├── doctor/

│   │   └── modules/        # Individual diagnostic checks
│   └── config-ui.py        # Python config TUI
├── docs/
│   ├── installation.md
│   ├── troubleshooting.md
│   └── review/             # Code review reports
├── .github/
│   └── workflows/

Key Principles

  • bin/ vs src/: bin/ holds user-facing CLI entry points (thin wrappers). src/ holds all implementation logic.
  • install vs runtime: Install logic in src/install/, runtime/daily-use in src/modules/ and bin/.
  • No top-level scripts: Every script lives in a subdirectory with a clear purpose.
  • GitHub standard: README, LICENSE, CONTRIBUTING, CI workflow, docs/.
