# File Lines Severity Issue Recommendation
Safety Dangerous patterns that could cause data loss or code execution
1 runtime-scripts/uninstall-select.sh 114-117 Critical eval on constructed command strings. comp_cmds[] stores rm -rf commands as string templates. At line 117, eval "${comp_cmds[idx]}" executes them. Any path variable containing spaces, ;, or $ enables arbitrary command injection. Additionally, the [[ -e "$path" ]] check in add_comp() does not expand globs, so icon and bridge-temp entries never appear in the menu (silent dead code for glob patterns). Remove comp_cmds[] entirely. Store only paths in components[]. Execute rm -rf "$path" directly in the for-loop. Handle globs via compgen -G in add_comp(). See patch below.
2 uninstall.sh 95-98 Major Unchecked wildcard rm for bridge temp files. rm -rf /tmp/fusion360-* runs unconditionally. If the glob expands unexpectedly (e.g., due to a parallel process creating files with surprising names), the || true swallows errors. The echo on line 98 always claims success. Guard with compgen -G '/tmp/fusion360-*' before running rm -rf. Only print "Removed" when files actually existed.
3 runtime-scripts/uninstall-select.sh 82 Major Unquoted input subject to glob expansion. for num in $selection subjects user input to pathname expansion. If the user types * or ?, the shell expands them against the filesystem. Use read -ra nums <<< "$selection" or wrap with set -f/set +f.
4 doctor/00-common.sh 18 Medium exec > >(tee ...) without fallback. Line 18 redirects all stdout/stderr through tee. If tee fails (disk full, path unwritable) or if process substitution is unavailable (old shells, restricted envs), all output is silently lost. Use a simpler redirection pattern with fallback: exec > >(tee "$REPORT_FILE") 2>&1 || exec > "$REPORT_FILE" 2>&1. Or use a named pipe approach.
5 install-scripts/00-common.sh 149 Medium Unvalidated PFX_DIR in wineserver lock removal. rm -f "$PFX_DIR/pfx/.wineserver.lock" runs without checking if PFX_DIR is set. If PFX_DIR is somehow unset, this becomes rm -f /pfx/.wineserver.lock. Add a guard: [[ -n "${PFX_DIR:-}" ]] && rm -f "$PFX_DIR/pfx/.wineserver.lock".
Duplication Redundant or overlapping logic
6 install-scripts/00-common.sh 72-150 Major Duplicate process lifecycle management. kill_installer() in 00-common.sh and kill-wine-proton-fusion-nuclear.sh both kill Wine/Proton processes but use completely different strategies:
  • 00-common.sh: scans /proc/PID/exe + pgrep, deduplicates, kills tracked installer PID separately, verifies survivors, removes lock file
  • kill-wine script: three pkill passes (TERM, sleep, KILL) by pattern matching
The 00-common.sh version is more thorough but both exist in isolation. Fixes to one won't benefit the other. 		Extract shared kill logic into launcher-functions.sh as kill_fusion_processes(). Have 00-common.sh::kill_installer() and the standalone script both call it. The combined function should use pgrep + /proc scanning (best of both) with graceful SIGTERM then SIGKILL escalation.
7 install-scripts/* all Medium Redundant SCRIPT_DIR calculation. Each install script that defines SCRIPT_DIR uses slightly different logic: 00-common.sh calculates it as "$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)", while sourced scripts inherit it from install.sh but install-scripts/00-defaults.sh also recalculates it. Hardcoded "$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)" appears in multiple scripts. Rely on one source of truth: set SCRIPT_DIR once in install.sh and reference it everywhere. Remove redundant calculations. For standalone scripts, use a consistent pattern relative to the known repo root.
Error Handling Missing guards and silent failures
8 runtime-scripts/ (multiple) various Major Missing set -euo pipefail in runtime scripts. Only kill-wine-proton-fusion-nuclear.sh uses it. The following scripts lack it: fusion-browser.sh, fusion-callback-handler.sh, fusion-browser-listener.sh, fusion-gray-overlay-event-killer.sh, register-protocols.sh, health-check.sh, uninstall-select.sh. Failures in intermediate pipeline stages or unset variables go undetected. Add set -euo pipefail to every standalone script (not sourced). For sourced scripts like 00-common.sh, document that the caller must set it.
9 doctor.sh 11 Minor Inconsistent set flags: set -uo pipefail without -e. All other top-level scripts use the full set -euo pipefail. Without -e, commands that fail mid-script keep running, potentially producing a misleading summary. Add -e to make it set -euo pipefail. The doctor modules already use || true on inherently-fallible commands.
10 doctor/00-common.sh 13-23 Medium parse_args silently ignores unknown flags. Only --save and --quick are recognized. A typo like --quik or --help falls through silently. Add a catch-all *) case that prints usage and exits, or at minimum warns on unrecognized arguments.
11 runtime-scripts/launcher-functions.sh 237-270 Major DPI registry writes lack input validation and error checking. apply_fusion_wine_dpi() manipulates user.reg via sed -i and echo >> with three problems:
  1. [[ "$dpi_value" -eq 96 ]] errors if dpi_value is empty/non-numeric
  2. Sequential sed -i calls aren't atomic — partial failure corrupts the registry
  3. No || fallbacks on sed/echo/grep calls
  1. Validate: [[ "$dpi_value" =~ ^[0-9]+$ ]] || return 1
  2. Combine sed ops into a single -e invocation
  3. Add || echo "warning: ..." >&2 on each reg-modifying call
Consistency Divergent conventions and paths
12 install-scripts/37-config.sh 34-54 Major Config format inconsistency between install-time and save-time writers. Install-time: plain heredoc with raw interpolation (PROTON=$GE_PROTON). Run-time (save_config()): printf "%q" for shell-safe escaping. A fresh-install config cannot be safely re-sourced if values contain spaces or special chars. The Python UI also uses a third format via shlex.quote. Use printf "%q" consistently in both config writers. The Python UI's shlex.quote-based writer already handles this correctly; the install-time writer should match.
13 runtime-scripts/launcher-functions.sh 302-308 Major Browser bridge detection regression. register_wine_browser_bridge() now only checks whether the [Software\Wine\WineBrowser] section header exists, not whether the actual Browsers value matches $BROWSER. If the section exists from a prior configuration with a different browser, the update is silently skipped. After checking section existence, also grep for the actual $BROWSER value: grep -qF "$BROWSER" "$user_reg" && return 0 before deciding to skip.
14 runtime-scripts/launcher-functions.sh 268 Medium DPI log truncated instead of appended. DPI setting output uses > (overwrite) instead of >> (append), losing diagnostic history across launches. Change > to >>, or add log rotation if size is a concern.
15 install-scripts/30-prefix.sh 17-20 Medium Conflicting Wine environment variables. winetricks invocation sets both STEAM_COMPAT_DATA_PATH and WINEPREFIX simultaneously. These point to different paths by convention — one may override the other depending on winetricks version, causing components to install in the wrong location. Use only one prefix mechanism consistently. If using Proton's STEAM_COMPAT_DATA_PATH, drop WINEPREFIX. If winetricks requires WINEPREFIX, set it to $PFX_DIR/pfx.
Code Quality Best-practice improvements
16 doctor/00-common.sh 31 Minor echo -e "$*" is a bashism. POSIX echo doesn't support -e. In some shells it prints -e literally. Works with #!/usr/bin/env bash but fragile if sourced from /bin/sh. Replace with printf '%b\n' "$*" for POSIX portability.
17 runtime-scripts/launcher-functions.sh 41-72 Minor printf "%q" output varies across bash versions. save_config() uses printf "%q" for shell-safe escaping. Output format differs between bash versions — some use $'...', others backslash escaping. Older bash may not parse $'...' correctly in sourced configs. Consider a non-shell config format (INI, JSON), or use single-quote wrapping (as the Python UI's shlex.quote does), which all bash versions handle correctly.
18 runtime-scripts/launcher-functions.sh 252-263 Medium Sequential sed -i calls create TOCTOU window. Two back-to-back sed -i invocations on user.reg (delete-then-append) leave a window where concurrent launcher instances could read a partially-modified file. Combine into single sed -e with multiple expressions, or write to temp file and atomically rename.
19 doctor/00-common.sh 26 Minor emit() function wrappers are unnecessary. emit() { echo -e "$*"; } is a thin wrapper that adds no value over inline echo -e (or better, printf). Creates unnecessary indirection. Remove emit() and call echo -e (or printf '%b\n') directly at the three call sites.

Proposed Work Plan

Ordered by risk reduction: fix safety-critical issues first, then consolidation, then error handling and consistency. Each step is independently verifiable.
  1. Fix critical eval in uninstall-select.sh — Rewrite add_comp() and execute loop to use direct rm -rf "$path". Remove comp_cmds[] array. Handle glob patterns with compgen -G. Add set -euo pipefail. Files: runtime-scripts/uninstall-select.sh
  2. Guard all unprotected rm -rf — Add existence checks before destructive operations in uninstall.sh (bridge temp files) and validate glob expansion. Files: uninstall.sh
  3. Consolidate process management — Extract shared kill function into launcher-functions.sh. Refactor both 00-common.sh::kill_installer() and kill-wine-proton-fusion-nuclear.sh to use it. Use combined pgrep + /proc scan with graceful escalation. Files: runtime-scripts/launcher-functions.sh, install-scripts/00-common.sh, runtime-scripts/kill-wine-proton-fusion-nuclear.sh
  4. Fix exec without fallback — Add fallback in parse_args() for when exec > >(tee ...) fails. Files: doctor/00-common.sh
  5. Add set -euo pipefail to all standalone scripts — Audit every runtime script, add the guard. Add || true on inherently failing commands to preserve expected behavior. Files: runtime-scripts/*.sh (except launcher-functions.sh which is sourced)
  6. Fix DPI validation in launcher-functions.sh — Add input validation, combine sed ops, add error fallbacks.
  7. Fix browser bridge detection regression — Verify $BROWSER value matches the registry, not just section header existence.
  8. Fix config format inconsistency — Make install-time and save-time config writers use the same printf "%q" pattern.
  9. Fix doctor.sh set flags — Add -e to match project convention.
  10. Minor quality fixes — echo -e → printf '%b\n', DPI log append, add usage to parse_args, remove emit() wrapper, unify SCRIPT_DIR computation.

Detailed Patches

1. uninstall-select.sh — Remove eval, fix globs

Replace the add_comp() function and execute loop:

- comp_cmds=() + # (remove this array entirely) - add_comp() { - local name="$1" path="$2" cmd="$3" - if [[ -e "$path" ]]; then - local size - size=$(du -sh "$path" 2>/dev/null | cut -f1) - components+=("$path") - comp_names+=("$name") - comp_sizes+=("$size") - comp_cmds+=("$cmd") - fi - } + add_comp() { + local name="$1" path="$2" + local size="" exists=false + if [[ "$path" == *\** ]]; then + compgen -G "$path" &>/dev/null && exists=true + elif [[ -e "$path" ]]; then + exists=true + size=$(du -sh "$path" 2>/dev/null | cut -f1) + fi + if $exists; then + components+=("$path") + comp_names+=("$name") + comp_sizes+=("$size") + fi + } All callers change from 3-arg to 2-arg (remove cmd string). - eval "${comp_cmds[idx]}" + local path="${components[idx]}" + if [[ "$path" == *\** ]]; then + rm -rf $path 2>/dev/null || true + else + rm -rf "$path" + fi

2. uninstall.sh — Guard bridge temp files

- echo " Removing bridge temp files..." - rm -rf /tmp/fusion360-* 2>/dev/null || true - echo " Removed: /tmp/fusion360-*" + if compgen -G '/tmp/fusion360-*' &>/dev/null; then + rm -rf /tmp/fusion360-* + echo " Removed: /tmp/fusion360-*" + else + echo " [SKIP] No bridge temp files found." + fi

3. Consolidate kill function into launcher-functions.sh

# Add to runtime-scripts/launcher-functions.sh: kill_fusion_processes() { local user; user=$(id -u) local patterns=( "wineserver" "wine" "proton" "xalia" "streamer" "Fusion360" "FusionClientDownloader" "AdskIdentity" "adexmtsv" "steam\\.exe" "node\\.exe" "fusion-gray-overlay" ) local pids=() # Method 1: pgrep by cmdline for pattern in "${patterns[@]}"; do while IFS= read -r pid; do [[ -n "$pid" ]] && pids+=("$pid") done < <(pgrep -u "$user" -f "$pattern" 2>/dev/null || true) done # Method 2: /proc/PID/exe scan for proc in /proc/[0-9]*/exe; do local exe; exe=$(readlink "$proc" 2>/dev/null || true) [[ "$exe" == *wine* || "$exe" == *proton* ]] || continue local pid="${proc%/exe}"; pid="${pid#/proc/}" pids+=("$pid") done # Deduplicate local unique=() for pid in "${pids[@]}"; do [[ -z "$pid" ]] && continue case " ${unique[*]} " in *" $pid "*) continue ;; esac unique+=("$pid") done (( ${#unique[@]} == 0 )) && return 0 # Term gracefully then force for pid in "${unique[@]}"; do kill "$pid" 2>/dev/null || true; done sleep 0.3 for pid in "${unique[@]}"; do kill -9 "$pid" 2>/dev/null || true; done sleep 1 # Verify local survivors=0 for proc in /proc/[0-9]*/exe; do local exe; exe=$(readlink "$proc" 2>/dev/null || true) [[ "$exe" == *wine* || "$exe" == *proton* ]] || continue survivors=$((survivors + 1)) done (( survivors == 0 )) && echo " [lifecycle] Killed successfully." \ || echo " [lifecycle] $survivors process(es) still running." }

Then kill-wine-proton-fusion-nuclear.sh simplifies to:

- #!/usr/bin/env bash - set -euo pipefail - USER_NAME="$(id -un)" - # ... 26 lines of pkill patterns ... + #!/usr/bin/env bash + set -euo pipefail + SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)" + source "$SCRIPT_DIR/runtime-scripts/launcher-functions.sh" + kill_fusion_processes

And 00-common.sh::kill_installer() gains source "$SCRIPT_DIR/runtime-scripts/launcher-functions.sh" at the top and replaces its body with a call to kill_fusion_processes, keeping only the INSTALLER_PID-specific logic and lock file removal.
