runtime-scripts/uninstall-select.sh 114–117 🔴 Critical eval on constructed command strings. The comp_cmds array stores rm -rf command strings built from hardcoded templates with $HOME expansion. At line 116 these are executed via eval "${comp_cmds[idx]}". If any path variable ever contains shell metacharacters (spaces, ;, $), arbitrary command execution is possible. The unquoted $HOME in the templates compounds the risk. Replace eval with direct execution using properly quoted arrays:
rm -rf "$path" called inline, not through a string. Store paths, not shell code.
runtime-scripts/launcher-functions.sh 237–270 🟠 Major DPI registry writes lack error handling and input validation. The rewritten apply_fusion_wine_dpi() manipulates user.reg directly via sed -i and echo >>. Three problems:
  1. [[ "$dpi_value" -eq 96 ]] at line 240 will emit a bash error if dpi_value is empty or non-numeric (possible if config is misconfigured).
  2. Multiple sequential sed -i calls on the same file are not atomic; if the first succeeds but the second fails, the registry is left partially modified.
  3. Unlike the old code which had || { echo warning... } fallbacks, none of the new sed/echo/grep calls check exit status. Silent failures go undetected.
  1. Validate that dpi_value is a positive integer before arithmetic comparisons:
    [[ "$dpi_value" =~ ^[0-9]+$ ]] || return 1
  2. Combine the two sed operations into a single invocation, or use a temp-file + atomic rename pattern.
  3. Add || { echo "warning: ..." >&2; } on each sed call, or set set -e so failures halt. At minimum, log when writes fail.
runtime-scripts/launcher-functions.sh 302–308 🟠 Major Browser bridge detection regression. register_wine_browser_bridge() now only checks whether the [Software\\Wine\\WineBrowser] section header exists, not whether the actual Browsers value matches $BROWSER. The old code grepped $BROWSER in the reg query output. If the section exists but points to a different browser path (e.g., after reconfiguring BROWSER), the new code silently skips the update. After checking section existence, also grep for the actual $BROWSER value inside the section. Example:
grep -q '^\[Software\\\\Wine\\\\WineBrowser\]' ... && grep -qF "$BROWSER" ... && return 0
runtime-scripts/uninstall-select.sh 82 🟠 Major Unquoted variable subjected to glob expansion. for num in $selection splits the user's input on whitespace (intentional for space-separated numbers), but also subjects each token to pathname (glob) expansion. If the user types characters like * or ?, unexpected file matching occurs. Use read -ra nums <<< "$selection" (bash) or set -f before the loop and set +f after to disable globbing during parsing.
install-scripts/37-config.sh 34–54 🟠 Major Config file written without value escaping. The install-time config writer uses a plain heredoc with raw variable interpolation (PROTON=$GE_PROTON). Values that contain spaces or special characters produce broken config files. Meanwhile, save_config() in launcher-functions.sh uses printf "%q" for proper shell escaping. These two writers produce inconsistent formats — a config saved via the Python UI will be properly quoted, but a fresh install config won't be. Use printf "%q" (or shlex.quote in Python) in both config writers. Enforce a single canonical format. The Python UI's write_config_values already does this correctly.
runtime-scripts/ (multiple) various 🟠 Major Most runtime scripts lack set -euo pipefail. Only kill-wine-proton-fusion-nuclear.sh uses it. fusion-browser.sh, fusion-callback-handler.sh, fusion-browser-listener.sh, fusion-gray-overlay-event-killer.sh, register-protocols.sh, and health-check.sh all lack it. Failures in intermediate pipeline stages or unset variable references go silently unnoticed. The uninstall-select.sh script also lacks it, making the eval issue worse. Add set -euo pipefail to every standalone script. For sourced scripts, document that they expect set -euo pipefail from the caller (as install.sh already does).
runtime-scripts/launcher-functions.sh 268 🟡 Medium DPI log truncated instead of appended. The old code used >> to append DPI setting output to $FUSION_DPI_LOG_FILE. The new code uses > which overwrites the file each launch. This loses diagnostic history that could be useful for troubleshooting DPI issues across launches. Change > to >> on line 268 to preserve log history, or add a log rotation mechanism if size is a concern.
install-scripts/30-prefix.sh 17–20 🟡 Medium Conflicting Wine environment variables. The winetricks invocation sets both STEAM_COMPAT_DATA_PATH (Proton's prefix location) and WINEPREFIX (Wine's prefix location) simultaneously. These point to different paths by convention (STEAM_COMPAT_DATA_PATH is the parent of pfx/, while WINEPREFIX points directly at the prefix root). Depending on winetricks version, one may override the other, leading to components being installed in the wrong location. Use only one prefix mechanism consistently. If using Proton's STEAM_COMPAT_DATA_PATH, drop WINEPREFIX. If winetricks requires WINEPREFIX, set it to $PFX_DIR/pfx and ensure it matches.
doctor/00-common.sh 11–20 🟡 Medium parse_args silently ignores unknown arguments. Only --save and --quick are recognized. Any other argument (typo, --help, etc.) falls through with no error or feedback. The user believes a flag was applied when it wasn't. Add a *) catch-all case that prints an error and exits, or add a --help flag. At minimum, warn on unknown arguments.
runtime-scripts/launcher-functions.sh 252–253, 262–263 🟡 Medium Sequential sed -i calls create TOCTOU window. Two back-to-back sed -i invocations on user.reg (delete-then-append pattern) leave a window where another process could read a partially-modified file. While the risk is low in single-user scenarios, concurrent launcher instances (e.g., from a misconfigured double-click) would race. Combine both operations into a single sed invocation using multiple -e expressions, or write to a temp file and atomically rename.
doctor/00-common.sh 31 🟢 Minor echo -e is a bashism. POSIX echo does not support -e; in some shells it would literally print -e. Since the shebang is #!/usr/bin/env bash this works in practice, but it's fragile if ever sourced from a /bin/sh script. Replace echo -e "$*" with printf '%b\n' "$*" for portability. Or use $'...' ANSI-C quoting in bash.
runtime-scripts/launcher-functions.sh 41–72 🟢 Minor printf "%q" output format varies across bash versions. save_config() uses printf "%q" for shell escaping. The output format differs between bash versions — some use $'...' quoting, others use backslash escaping. When load_config() sources the file, older bash versions may not parse $'...' correctly, leading to config loading failures. Consider using a non-shell config format (INI, JSON) or use a consistent quoting mechanism. The Python UI's approach (shlex.quote) produces single-quote wrapping that all bash versions handle correctly.
doctor.sh 12 🟢 Minor set -uo pipefail without -e. doctor.sh uses set -uo pipefail but omits -e (errexit). This is inconsistent with install.sh which uses the full set -euo pipefail. Without -e, commands that fail mid-script don't halt execution, and the summary may report misleading pass/fail counts. Add -e to make it set -euo pipefail. The individual doctor module checks use || true where needed (e.g., find ... || true) so they won't be affected.

Architecture Notes

Design observations (not defects):
  • Dual config writers — Config is generated at install time (37-config.sh) and re-saved at runtime (save_config() + Python UI). These use different escaping strategies, creating format ambiguity.
  • Mixed ownership — The install scripts are sourced into a single shell (they inherit set -euo pipefail from install.sh), but runtime scripts are standalone executables with no shared error-handling contract.
  • IPC via filesystem — Browser bridge and callback handler use /tmp/fusion360-* directories with atomic rename (mv .partial → .request). This is correct for single-instance use but has no cleanup guarantee if the listener crashes.
  • Registry manipulation strategy shift — The diff replaces proton run reg add (safe, goes through Wine's registry locking) with direct sed/echo on user.reg (fast but bypasses locking and format guarantees).
